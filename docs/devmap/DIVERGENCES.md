# devmap (Rust) vs Python Baseline Divergence Ledger (R3)

This document tracks deliberate, documented divergences between Python `devcouncil.indexing` / `codeintel` behavior and `devmap` (Rust).

**The Python side is history.** The Python engine was retired in Phase 7 (2026-09-10) and no Python surface exists in this tree; every "Python behavior" cell below is the frozen baseline the Rust kernel was ported against, kept so a divergence can still be read against what it diverged from, not a description of anything that runs.

## Baseline regeneration decisions

- **2026-08-12 — canonical snapshot schema repair:** regenerate all Phase 1 golden snapshots after fixing the snapshotter to emit PLAN §7.8 identities (`node.id/kind/path/line/name/exported`, `edge.source/target/kind/confidence`, `dead.id/confidence`). The prior files silently wrote empty `qualified_name`/`span` fields that do not exist on the frozen graph schema and therefore were not a usable parity baseline. `tools/snapshot/test_generate_snapshots.py` proves graph-build failures cannot be rewritten as authoritative empty snapshots.
| **K5** | Every file the Python engine could not parse counted as a parse failure, prose and data formats included | A format with no grammar (`.md`, `.json`, `.toml`, …) contributes a `File` node and is `ExtractionEngine::NotApplicable`, not a parse failure; a malformed file of a grammar language still is | `parse_failed` in `build_history` and status now means "a source the kernel should have parsed and could not". Tests `k5_prose_formats_are_not_parse_failures_but_broken_files_still_are`, `k5_build_history_parse_failed_excludes_grammarless_prose` |
| **K7** | The Python walker skipped generated directories by name only (`target`, `node_modules`, …) | Any directory carrying a `CACHEDIR.TAG` with the standard signature is skipped by discovery, by `--affected`, and by the watcher's enqueue — in addition to the name list | Measured: 1,041 of 2,363 indexed files on DevCouncil were cargo output under untracked `target-*` dirs. Tests `k7_a_cachedir_tagged_directory_is_never_walked_or_indexed`, `k7_watcher_events_inside_a_cache_directory_are_never_enqueued`, `k7_a_cachedir_tag_without_the_signature_is_not_a_cache_directory` |
| **SEAM-1** | One `dev map` committed one Python generation and wrote the agent guides afterwards, so the store never knew `AGENTS.md`/`CLAUDE.md` until the next build | A repository whose guides a build creates or changes gets a second, incremental kernel build for those files; a repository that already carries them commits exactly one generation | Store, artifacts and freshness stamps describe the same tree. Tests `test_full_map_commits_one_generation_and_records_progress`, `test_map_artifacts_reuses_generation_when_nothing_changed` |
| **SEAM-2** | A failed Python build could stamp a lean, `graph_degraded` map over a healthy generation | A failed or timed-out kernel build raises `DevMapEngineError` (with a diagnosis code) and leaves the prior artifacts byte-identical; there is no lean map | Tests `test_map_artifacts_propagates_a_kernel_failure_without_writing_a_map`, `test_map_artifacts_keeps_the_prior_artifacts_when_the_kernel_times_out` |
