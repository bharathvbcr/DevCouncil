# DevCouncil v0.2.5 Release Notes

DevCouncil v0.2.5 and DevMap v0.2.5 are the same product version. The npm package,
the Go host (`devcouncil` / `dev`), and the Rust workspace (`devmap`, `dcstore`,
`dcverify`, `dcgrep`) all report **0.2.5**.

The last release published to GitHub is **v0.2.3**. **v0.2.4 was never published.**
Its notes stay in [v0.2.4.md](v0.2.4.md) so the release line has a step, and this
release is that draft plus the commits after the local tag `v0.2.4` (`6b889fd7`).
Do not push the `v0.2.4` tag. Anyone upgrading from v0.2.3 gets both.

### Code intelligence: extraction schema 98 (extract-v98)

The extract-v98 bundle landed across four successive landings (`37b9f9f5`, `abfb7c65`,
`0bd75c8d`, `115266fc`), bumping `EXTRACTION_SCHEMA_VERSION` to `"98"`. Stored cache identities
name `{ANALYZER_VERSION}:extract-v98`. The proof test
(`rust/devmap-cli/tests/a_v97_extraction_is_not_served_after_the_bump.rs`) verifies that v97
payloads are refused and never served to v98 keys.

Six new side tables were added to `Extraction` (each `serde(default)` and omitted when empty):
`jvm_decls`, `package_scopes`, `local_extents`, `decl_gaps`, `recovered_decl_ranges`, and
`dynamic_dispatch`.

- **Kotlin declaration-loss recovery (`kotlinloss.rs`, `kotlinsemi.rs`):**
  - Declarations swallowed or misparsed as expressions by tree-sitter (such as `@Ann(args)`
    one-liners or `fun f() = 1` parsed as assignments) are detected via AST checks and
    repaired through wrapper re-parsing, publishing their ranges to `recovered_decl_ranges`.
  - One-line Kotlin class bodies (`class C { companion object { … } }`) are repaired with a
    same-length separator.
  - Hidden-error charging: an AST node carrying an unexposed parse error is charged, ensuring
    hidden missing separators cannot produce a false Clean status. The hidden-error charge is
    scoped to Kotlin.
  - Row 16 rewrite loops until clean or capped (up to 32 passes, 512 separators), separating
    declarations that share a line and bounding nested chains.
  - Settled tables for charged Kotlin regions are derived from settled results.
- **Swift residue typing & bare-cast refusal (`swiftscope.rs`):**
  - Resolves property wrappers, parameter-receiver locals, metatypes (stating no type), and
    closure-property typing.
  - Wrapper declarations are read once per file rather than once per property.
  - Tuple patterns in loops and conditions rebind names without emitting spurious `LocalBinding`
    records, preserving main parity and preventing true edge losses.
  - Abstains when a Swift name is declared twice in a file as different nested types.
  - Swift calls with no spelling are refused at the call gate with diagnostic logging.
  - Swift members hung off a bare `as?` / `as!` cast are refused and recorded with a diagnostic note.
- **SQL DDL recovery (`sqlddl.rs`):**
  - Recovers SQL tables and views swallowed by grammar limitations (e.g. check constraints
    or complex column definitions).
  - SQL statement renames compose cleanly, moving qualified names only for holders and never
    removing grammar-clean elements.

### Language resolution enhancements

- **Java records, compact constructors & enum constants (`langdecl/java.rs`, `langfields.rs`):**
  - Added AST declaration and field extraction for Java `record` declarations, compact
    constructors (`public RecordName { ... }`), canonical constructors, and enum constants
    (`enum Planet { EARTH }`).
  - Record components automatically emit accessor methods and component field bindings.
  - **Constructor collapse:** Only a Java record collapses with its canonical/compact constructor
    into one declaration identity (tagged with signature `"record"` / `JAVA_RECORD_SIGNATURE`),
    restoring `UniqueGlobal` resolution on `new Record(..)`. Plain Java classes and their
    constructors remain distinct declaration symbols.
  - **Implicit `java.lang.*` external resolution:** Unqualified Java type names with no prior
    in-file or imported binding route resolve to `java.lang` as `External` (e.g. `String`,
    `Object`), failing closed if the enclosing scope declares type parameters of that name.
- **TypeScript / JavaScript barrels & namespaces (`namespace_over_a_barrel.rs`):**
  - Namespace handles over barrels (`import * as ui from './index'`) follow re-export chains
    (`export * from './tabs'`, `export { default as App } from './app'`, `export { x } from ...`).
  - JS/TS types resolve through their own module's scope (`ts_module_scoped_types.rs`).
  - Imported type member resolution ignores re-exports of the importing file.
  - Default exports are not re-exported through `export *` per ECMAScript specification.
- **CommonJS member export publication & literal constant protection:**
  - `exports.x = ...` and `module.exports.x = ...` are published as export symbols when uniquely
    assigned in the file, and are bound by plain or aliased destructuring. Ambiguous or reassigned
    exports are withheld with an explicit `CJS_WITHHELD_PREFIX` gap reason.
  - Literal constants (`const HTTP_OK = 200`) are recognized as inert: calls to an imported literal
    constant remain references to the constant instead of fabricating call edges. Hoisted `void 0`
    is excluded from literal constant classification.
- **Go build-constraint variant sets (`go_variants.rs`):**
  - Cross-file platform/build-tag variants (`//go:build unix` vs `//go:build !unix`) within the same
    package are resolved as a unified callee variant set with dispatch-tier edges rather than
    ambiguous global fan-out or cross-package misses.
- **Language server (`--lsp`) bindings:**
  - `--lsp` binds only function or method names, ignoring non-callable symbols.
  - Protocol readout failures explicitly report their underlying cause.

### Resolution ambiguity budgets & graceful degradation

- **Ambiguity budget controls (`devmap-resolve`, `devmap-cli`):**
  Added configurable resolution limits to `devmap build`:
  - `--resolve-candidate-visits <N>`: maximum candidate-table entries resolution may visit.
  - `--resolve-retained-candidate-bytes <BYTES>`: maximum bytes of candidate lists retained.
  - `--resolve-ambiguity-evidence-bytes <BYTES>`: maximum bytes of ambiguity evidence.
  - `--resolve-degraded-candidates <N>`: number of candidates retained per capped list.
  - `--refuse-on-resolve-limit`: flag to force build refusal instead of degrading.
- **Graceful degradation:**
  Candidate lists exceeding budget limits degrade per list by dropping excess candidates while
  retaining a bounded sample (sized to Linux kernel scale), rather than failing the build.
- **Partial analysis tagging:**
  An exceeded resolution budget records a `coverage_gaps.resolution_budget` gap row, marks
  reachability as unreliable in `devmap-analyze`, and causes both exported repo map (`repo_map.json`)
  and code graph (`code_graph.json`) to declare `partial: true` with named reasons (`N name(s) capped,
  M candidate(s) dropped`).
- **Carried cap reporting:**
  Unchanged builds restate resolution budget caps carried by the stored generation
  (`latest_resolution_budget_gaps`).
- **Bounded identifier samples:**
  Gap records bound identifier samples to at most 10 names, 128 bytes each, 1024 bytes total, with a
  `+M more` tail. Truncations dropping zero candidates do not trigger cap or partial flags.

### Damaged store detection & refusal

- **Integrity probe on status:**
  `devmap status` probes SQLite full-text search index shadow tables. If corrupted, it reports
  `query_ready: false` and `search_index_damaged: true`, with the probe finding in `degraded_reason`.
- **Pre-write build refusal:**
  `devmap build` executes a cheap readable probe before writing. If damaged, it refuses with the
  store path, the corruption finding, and remediation steps (move or delete and rebuild), rather
  than exiting 0 with "unchanged".
- **Auto-quarantine parked (`docs/devmap/design/auto-quarantine-parked.md`):**
  Automatic renaming of corrupt stores was attacked and parked to prevent violating the "ownership
  first" boundary across concurrent agent worktrees.
- **Multi-worktree safety:**
  `refuse_if_owned_by_another_live_worktree` executes before any store mutation or integrity check.

### Process execution, session child stderr tail & signal safety (`dc-proc`)

- **Session child stderr tail:**
  Session children (`devmap build --lsp`, `dc-regress`) drain stderr to EOF on a dedicated thread,
  retaining only the last 4096 bytes (`SESSION_STDERR_TAIL_BYTES`).
- **Secret redaction on failure:**
  When a child exits non-zero (`LspDidNotRun::NonZeroExit`), stderr is redacted using `dc_redact`
  credential tables before reporting (`lsp.servers[].stderr_tail`). Unclosed pipes are reported
  with `stderr_tail_incomplete: true`.
- **Stdin write safety:**
  Writes to exited session children return an error rather than unhandled `SIGPIPE`. Short writes
  raising `SIGPIPE` leave nothing pending.
- **`argv[0]` preservation:**
  `dc_proc::resolve_outside` returns a `Resolved` struct preserving both the canonical executable
  path and the looked-up program name (`argv[0]`) for multiplexers like `rustup`. Config caches are
  keyed by runtime binary name.

### Storage & persistence performance

- **Parallel chunked payload serialization (`devmap-store/src/db/write.rs`):**
  Fresh file payloads (symbols, calls, references JSON) are serialized in parallel chunks of 64
  on scoped Rayon threads ahead of SQLite inserts, reducing cold write times by ~36% on large trees.
  In-flight memory is bounded in bytes with an in-order window, and serializer panics are caught and
  propagated without dropping payloads or poisoning the mutex.
- **Cache parse unlock (`devmap-store/src/extract_cache.rs`):**
  Cached extraction payloads are parsed after the SQLite connection guard drops, eliminating writer
  lock contention.
- **Write spans and cached inserts:** Cached node and literal inserts use a single-statement carry
  and report named write spans (`serialize`, `payloads`, `literals`).

### Query, navigation & CLI tools

- **Doc-drift auditor (`devmap doc-drift` & `devmap_doc_drift` MCP tool):**
  A deterministic, model-free scanner detecting Markdown references to code that no longer exists
  or has moved (missing target files, `#L...` line ranges past EOF, missing section anchors, or
  missing/moved symbols). Supports inline suppression via `<!-- devmap:doc-drift ignore-next-line -->`
  and `<!-- devmap:doc-drift ignore-file -->`.
- **Agent guide block ownership (`devmap build --manifest`):**
  DevMap can own and regenerate a dedicated `<!-- devmap:guide -->` block inside hand-written agent
  guides (`AGENTS.md`) without rewriting surrounding user documentation.
- **Verdict pinning concurrency fix (`devmap-query`):**
  Fixed a race where budget-trimmed query answers mis-verified against generation counters by
  checking the generation against `total` rather than `items.len()`.
- **Daemon freshness & drain cancellation (`devmap-serve`):**
  The daemon automatically verifies freshness after each drain. A drain starting during an active
  freshness walk cancels and re-arms it, with debounced and bounded post-drain walks.
- **Extraction schema in `--version`:**
  `devmap --version` reports store schema, code graph schema, extraction schema, and build hash.

### Verification rigor (`dc-verify` & Go host `verify`)

- **Expanded scan coverage:**
  Verification now scans untracked files, submodule bytes (including dirty submodules where the
  gitlink pointer moved), recreated files, binary-marked source, tool-state directories
  (`.devcouncil/`, etc.), and streamed index entries.
- **Submodule gitlink degradation:**
  Submodule pointer moves degrade verification with explicit naming of unscanned submodules
  (`GitState` report).
- **Replace-refs disabled:**
  Git replace-refs are disabled at both Go (`proc/git.go`) and Rust (`dc-proc`) seams via
  `-c core.useReplaceRefs=false`, preventing hidden credential commits.
- **Stub AST scanner & macro indexing:**
  Detects opaque stubs, stub-scanned binary-marked source, and lexer comments using whole-name
  path matching. `macro_rules!` scopes are indexed to avoid quadratic defs × calls checks and
  are capped per file.
- **Secret leak prevention:**
  Verification error outputs no longer echo raw diff lines. Panic hooks omit payload backtrace
  text, printing only the file and line.
- **Bounded execution:**
  Enforces a unified walk deadline across verify, and bounds input lengths (`bounded.rs`).
- **Explicit refusals:**
  Explicitly refuses nested repositories and explains hard-link refusals; treats `ENOTDIR` as a
  deleted path.
- **Ed25519 signature boundary:**
  Requires a trusted Ed25519 signature for discharging `llm_review` criteria.
- **Gusset pin:**
  Updated gusset pin to `e561435` (gusset v0.0.3, libc 0.2.191).

### SafeFile atomic rename retry (`safefile`)

- `OpenNoFollow` under `os.Root` retries (bounded at 16 attempts) when a regular file is atomically

  atomic publishers. Symlinks and FIFOs are immediately refused without retrying.

### Build and daemon

- **`devmap build` stops on Ctrl-C** (`5044ed56`, merge `7787808c`). One
  cancellation token runs from SIGINT into extraction and the serial
  budget-refusal retry. The first Ctrl-C makes the build return at its next
  file without committing a generation, and the process exits **130**
  (`rust/devmap-cli/src/interrupt.rs:22`, `main.rs:404`). A second Ctrl-C, or
  any Ctrl-C after extraction has finished and the build is persisting, exits 130
  at once rather than being acknowledged and ignored. The daemon trips the same
  flag from shutdown and from SIGTERM/SIGINT arriving mid-drain. Files refused by
  a cap are counted as cap-refused, never as cancelled.
- `devmap build --full` re-parses every source and writes a full generation;
  `--verify-rows` is its cheap half (it re-derives stored edge validity but keeps
  incremental extraction); `--force` is unrelated to both: it needs `--manifest`
  and replaces a foreign repo map or code graph (`commands/build.rs:35-80`).
- Every relative root is anchored and lexically cleaned once at the CLI boundary
  (`9cbd0f2b`). Budget refusals are named in `dead`, `affected` and `explore`
  caveats (`416c7ee1`), and an unreadable blast basis is unavailable content, not
  a mismatch (`a49c42bf`). Daemon status joins the analysis reason (`8bd6d4a1`).

### Command policy (owner decision, 2026-10-24)

Measured against agent transcripts, these rungs refused commands agents run on
almost every task. The ladder now reads them instead:

- **Variables.** A pre-pass (`policy/command_bindings.go`) rewrites a leading
  `~`, `$HOME`, `$TMPDIR` and every variable the line assigns a literal value —
  `f=x; …`, `export W=…`, each item of a `for` list — and judges each reading.
  `F=.env; cat $F` is refused as a secret read; `cat ~/x` is judged as the path
  it names. A variable the line does not bind is judged by its spelling rather
  than refused (`cat $f`, `cp a $W/b`, `git log main..$b`); a command
  substitution still is. Loosens: a parent environment can point an unbound
  variable at a path the gate did not see.
- **Temporary directories.** A write under `os.TempDir()`, `/tmp` or
  `/private/tmp` is allowed although it leaves the root, symlinks resolved, and
  an unmodelled program handed such a path is not refused for it. A root that
  itself lives in a temporary directory gets no allowance.
- **Read-only git.** `-c` with a presentation key (`core.pager` set to a plain
  pager, `core.quotepath`, `color.*`, `log.*`, `diff.*` layout keys) or
  `core.hooksPath`, and `GIT_PAGER`, `GIT_INDEX_FILE` inside the root and the
  locking and pathspec variables, no longer refuse `diff`/`log`/`show`/`status`.
  `-c` keys that run a program stay refused.
- **`--no-verify`** is no longer a git-safety refusal; `--no-gpg-sign` is. The
  command-parity snapshot records the one-row divergence.

### Store schema 29 (27 to 29), reader floor 29

The store schema moves from **27 to 29** in one release: v28 (payload-scoped rows)
and v29 (compressed extractions). `MIN_READER_SCHEMA_VERSION` is **29**
(`rust/devmap-store/src/schema.rs`), up from 25.

What changed:

- **v28, payload-scoped rows.** A symbol, literal or full-text row belongs to the file
  payload that produced it, and a file's payload and its digest rows carry a validity range
  of generations, instead of every generation copying its rows. `generation_nodes`,
  `generation_literals`, `generation_file_rows`, `generation_file_digests` and
  `nodes_fts_map` are now views over `payload_nodes`, `payload_literals`, `file_rows` and
  `digest_rows`. A payload is identified by a digest of what was extracted. This cuts the
  write cost of a one-file edit (design note and measurements:
  `docs/devmap/design/store-write-cost-proposal.md`, Appendix B).
- **v29, compressed extractions.** `file_payloads.extraction_json` is one zstd frame per
  payload (level 1, content checksum, no dictionary), and `entry_wiring_json` holds the
  runtime entry-point wiring so `devmap affected` decompresses nothing. The digest still
  covers the JSON text, so payload identity is unchanged. On a real 1,896-payload store the
  file went from 348.8 MB to 166.8 MB (Appendix C of the same note). A frame that is
  damaged, truncated, declares no size, declares more than 64 MiB or decodes to another size
  than it declares is refused by name.
- **New dependency:** `zstd =0.14.0` (`default-features = false`) in `devmap-store`,
  owner-approved. Consumers that vendor `devmap-store` take it with the schema.

What an upgrade means:

- **Old readers refuse.** Measured with a schema-27 binary (main at `080ef6e4`) against a
  schema-29 store: query commands fail with `schema version 29 can be read only by a reader at
  schema 29 or newer, and this one reads schema 27; update the binary that embeds devmap-store
  (re-vendor or rebuild it)`, `build` with `schema version 29 is not supported by this binary
  (schema 27); this devmap binary is older than the store`, and `status` answers
  `reader_ready: false` with `store schema is 29, newer than the 27 this binary speaks;
  install a matching or newer devmap binary`. Rebuild and reinstall every consumer that reads
  a DevMap store before pointing it at one.
- **Migration is one-way.** The first writer open of a 27 store runs the ladder in one
  transaction (verified per payload: each frame is decompressed and compared with the text it
  replaces), and a store the ladder cannot convert is refused and left at its old version. There
  is no downgrade: to go back, delete the store and rebuild it with the older binary.
- **Ownership comes before migration for `devmap build`.** A build of one worktree pointed
  at another live worktree's store is refused before the store is opened, so the refusal no
  longer leaves that store migrated under the other worktree's older binary. The read
  commands still open (and so migrate) a store before asking whose it is; that is recorded
  in `docs/devmap/design/auto-quarantine-parked.md` and is not fixed here.
- **Remedy text.** Store refusals that said `dev map doctor --fix` quarantines the store now
  say to move or delete it and run `devmap build`; the first command does not exist and the
  quarantine is parked.

### Policy: Prompt-input write protection (dh-4)

Landed in `84a9b35e` and merged in `067d3790` (`dh-4-prompt-inputs`):

- **Threat model:** An agent holding a valid write lease could alter instruction files
  (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`) read into future turns, or inject malicious server
  definitions into `mcp.json` or `.mcp.json` executed by the host.
- **Rung placement:** A dedicated prompt-input verification rung in `policy/promptinput.go`
  and `policy/file.go` (`EvaluateFileChange`) refuses agent writes to those five filenames at
  any directory depth, across every posture (including `yolo`). It also protects `.claude/`,
  `.cursor/`, and `.agents/` skill roots and plugin manifests under plugin roots discovered
  by Manvi.
- **Read/write separation:** The rung judges writes only; agents retain full permission to
  read their instruction documents. Reports `RuleRestrictedPath`.
- **Alias protection:** Hard links and symlink aliases resolving to root prompt inputs are
  detected and refused by identity (`syscall.Stat` device and inode checks).
- **Command plane coverage:** The policy applies across direct file writes, operand targets,
  git write commands, and link creation (`ln`).
- **Residuals:** Pinned in `gate/zadv_prompt_input_test.go`: shell interpreters (`sh -c`),
  `tar`/`unzip`, git state manipulations (`reset`, `merge`, `am`, `pull`, `cherry-pick`, `stash pop`),
  and directory-level `cp`/`mv`/`rsync` under all postures; `ed`, `awk -i inplace`, and
  `rm -rf .claude` under `yolo`.

### Search: dcgrep rank completeness and decoupled budgets

Landed across `2d47159f..b1ddade7` in `rust/dc-grep` and `backend/go_orchestrator/dc/dcgrep`:

- **Decoupled ceilings:** The trigram index postings ceiling (4,194,304 postings derived
  from 64 MiB / 16 B) and the ranked index budget are decoupled. Reaching the trigram
  ceiling halts trigram index population while `dcgrep search` continues via matcher scans;
  the walk and ranked index construction continue unhindered.
- **Strict 64 MiB bound on `lexical.bin`:** Enforced dynamically during construction
  (`e296787b`). Any document that would push `lexical.bin` over 64 MiB is cleanly excluded
  in whole rather than writing an unreadable or truncated binary.
- **Rank completeness contract:** Every `rank` query response now carries explicit
  completeness fields (`complete: bool`, `lexical_limit_reason`). `complete` is `true`
  if and only if:
  1. No ceiling stopped the build (`lexical_limit_reason` is `null`),
  2. The walk encountered zero read errors (`walk_errors == 0`), and
  3. No admissible text files were omitted (`lexical_unindexed == 0`).
- **Unindexed shortfall reporting:** `IndexResult` reports file omission counts categorized
  by cause in `lexical_unindexed_by_class` (`oversized`, `unsupported_encoding`, `binary`,
  `symlink`, `unrepresentable_name` with root-relative paths).
- **Client invariant validation:** The Go client enforces that `files + unindexed <= files_seen`
  and validates ceiling names against a strict closed set (`56854db2`, `48fde0c7`).
- **`Partial()` semantics:** Clarified to report admissible text files rather than generic
  readable files.

### Retrieval evaluation: rank-eval benchmark suite
