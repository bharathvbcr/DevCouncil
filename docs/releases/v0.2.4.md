# DevCouncil v0.2.4 Release Notes

DevCouncil v0.2.4 and DevMap v0.2.4 are the same product version. The npm package,
the Go host (`devcouncil` / `dev`), and the Rust workspace (`devmap`, `dcstore`,
`dcverify`, `dcgrep`) all report **0.2.4**.

This release consolidates LSP-backed resolution, natural-language query support,
expanded blast-radius analysis, strengthened MCP protocol conformance, and
correctness fixes across the Rust workspace.

## Highlights

### 1. LSP-backed symbol resolution (`devmap-resolve`)

A new `lsp` module allows the resolver to supplement tree-sitter edges with
Language Server Protocol responses, improving accuracy for implicit receiver
dispatch and cross-module call sites that tree-sitter grammars cannot see.
The LSP client manages its own deadline and kill-on-drop lifecycle, separate
from the bounded subprocess runner. Resolution honesty and audit regression
tests are extended to cover the new edges.

### 2. Natural-language query engine (`devmap-query`)

The `ask` module adds a ranked, natural-language interface to the code graph.
Ambiguous impact seeds are handled explicitly, and skeleton envelopes carry
truncation metadata so callers know when results are incomplete. New tests
cover ranking, ambiguous seeds, and envelope completeness.

### 3. Expanded blast-radius and regression analysis (`dc-regress`)

The blast module gains owner-aware test-signal propagation: when a change
touches a symbol, the graph now walks outward through ownership edges as well
as call edges, surfacing tests that cover the changed region through indirect
ownership. History analysis is refined with paired timing.

### 4. Virtual-override liveness correctness (`devmap-analyze`)

Heritage exemptions now correctly handle the `VirtualOverride` pattern: when
a derived type overrides a base-type method, the unresolved `self.method()`
call in the base no longer vetoes the heritage exemption. The fix preserves
the resolution reason on unresolved entries, filters virtual-override entries
from the namesake veto, and records the base-class call as a reached symbol.

### 5. Git-hook hardening (`devmap-cli`)

The hook subsystem receives conformance logic and tests ensuring that `devmap`
post-commit and post-checkout hooks validate arguments, handle concurrent
invocations, and degrade gracefully when the store is locked or the index is
stale. Explicit counter loops are replaced with `.enumerate()` per Clippy.

### 6. MCP server protocol hardening (`devmap-serve`)

Adversarial and spec-conformance test suites are expanded. The protocol module
gains additional request-validation logic, and the MCP handler adds stricter
envelope checks for malformed tool calls.

### 7. Store schema and edge-index improvements (`devmap-store`)

The store gains corruption-detection logic and a coverage-gap inventory test,
ensuring that a corrupt analysis row is never silently treated as missing.

### 8. Dead-code and liveness analysis improvements (`devmap-analyze`)

Dead-cluster detection and liveness analysis are refined for resolution-rate
awareness: clusters whose members are all below the resolution threshold are
no longer reported as dead, reducing false positives in polyglot repositories.

### 9. Subprocess boundary enforcement (`devmap-extract`)

The `every_child_process_in_the_kernel_goes_through_the_runner` test is
extended to exempt `lsp.rs`, which spawns interactive JSON-RPC servers that
manage their own deadline and cleanup — structurally incompatible with the
one-shot `run_bounded` runner.

### 10. Console streaming buffer hardening (`devcouncil/console`)

Output chunking prevents integer overflow when calculating chunk end windows
near `math.MaxInt`. Incomplete UTF-8 runs carried across window boundaries are
strictly bounded to at most one rune (`utf8.UTFMax - 1`), with oversized carry
flushed prior to the next window.

### 11. Secret redaction in test failure assertions (`dc-verify`)

Verification test failure messages withhold sensitive credentials and tokens
from stdout/stderr test logs, avoiding accidental secret exposure during
failing test runs.

## Compatibility

- **Store schema**: 23. The v22 → v23 step advances `user_version` only (no DDL) so a binary that does not know `ResolutionKind::LanguageServer` refuses the store instead of reading those rows as a neighbouring tier. Opening a schema-22 store for write migrates it; a schema-22 binary then refuses that store.
- **Node.js**: >=18 (unchanged).
- **Rust**: 1.89+ (unchanged).
- **Go**: 1.21+ (unchanged).

## Install

```sh
bash scripts/install.sh
```
