# DevCouncil v0.2.4 Release Notes

DevCouncil v0.2.4 and DevMap v0.2.4 are the same product version. The npm package,
the Go host (`devcouncil` / `dev`), and the Rust workspace (`devmap`, `dcstore`,
`dcverify`, `dcgrep`) all report **0.2.4**.

This release carries the work first stamped as **1.3.5** in 71e2cf9. That number
was a mistake — it was never a step in this release line — and it is withdrawn:
see [`v1.3.5.md`](v1.3.5.md). No GitHub Release was cut for it, but npm has
`devcouncil@1.3.5`; it is the same code as this release under the wrong number.

It adds an opt-in language-server pass to the resolver, a plain-language `ask`
query and a per-file `skeleton`, owners and test signal on `devmap blast`, and
richer write/first-read hooks. The store schema moves from **22** to **25**
and the extraction schema from **58** to **72** (see [Upgrade](#upgrade)).
Sections 13–20 record what the first draft left out: policy decisions on the
Gusset engine, `ask --evidence`, the unresolved-callers work, dead-list and
module-binding extraction fixes, and the language-policy skill. Sections 21–35
are the work merged after the first `v0.2.4` tag (`e8343fd0`), for which the tag
was moved: route middleware and the route views over MCP, receiver typing for
Rust, Go, Python and TS/JS, per-walk unresolved-site disclosure, a scoped and
re-ranked `ask`, AST-based stub detection and the `dc-redact` crate, criterion
dispatch in verification, a policy ladder that judges every clause, and
per-checkout task runs.

## Highlights

### 1. Opt-in language-server edges: `devmap build --lsp`

`devmap-resolve` gains an `lsp` module (908 lines). With `--lsp`, the resolver
asks a language server on `PATH` about call sites that are *still in the
unresolved ledger* after the syntax pass, and may add two new resolution kinds,
`LanguageServer` and `LanguageServerDispatch`, when the server names a target
inside the repository.

It can only add. The syntax resolver still owns every deterministic and
unique-global claim, and a missing, hung, oversized or disagreeing answer never
falls through to a bare-name `UniqueGlobal`. The pass is bounded — 256 files,
90 s for the whole pass, 8 s per request, 256 KiB per JSON-RPC frame — and
anything past a bound is reported as *did-not-run*, not as zero edges. Without
`--lsp` the build is unchanged, and the build readout's `lsp` field is `null`
rather than an empty report. `build_lsp_opt_in.rs` and
`language_server_edges.rs` hold both halves.

Dead-code and liveness analysis treat `LanguageServerDispatch` like
`AmbiguousGlobal`: a dispatch edge is evidence something may be called, not
proof of which target is.

### 2. `devmap ask` / `devmap_ask`: plain-language find

`devmap search --semantic` ranks names only. `ask` answers a question about
behaviour: TF-IDF over symbol names plus docstrings seeds the search, then
personalized PageRank over stored call edges re-ranks it. Nothing new is
stored. Edges below the deterministic rung are excluded unless
`--min-confidence` lowers the floor, and a seed neighbourhood that is all
speculative comes back empty *with a withheld line*, not as a silent zero.
Served over MCP as `devmap_ask`. Tests: `ask_ranking.rs`,
`ambiguous_impact_seeds.rs`.

### 3. `devmap skeleton` / `devmap_skeleton`: a file's definitions without bodies

Signature plus span for every definition in one file. A definition whose
signature was not extracted still returns its span and says so, and an empty
file and a path the index does not contain are different envelopes
(`presence`). Truncation carries its metadata. Test: `skeleton_envelopes.rs`.

### 4. `devmap blast` names owners and test signal

`dc-regress` blast gains recent owners of each changed path (name and email
only) and a per-module test signal. Owners are collected from `git log` under
a shared 5 s deadline, 32 commits and 256 KiB of output per path, and include
the pre-image path of a rename. The test signal has a separate `unavailable`
state: a walk that could not finish, or a renamed test it could not reconcile,
never reads as "no tests". Tests: `owners_and_test_signal.rs`,
`change_to_impact.rs`.

### 5. Write and first-read hooks paste real context

The write hook now renders a short pre-edit blast for the symbols whose spans
contain the edited range, from the generation already on disk, labelled stale
when the index is not fresh and bounded by its own wall-clock and character
budgets; a missed budget is stated and the hook still exits 0. It reads edited
ranges from Cursor `afterFileEdit`, Claude Write/Edit and Codex `apply_patch`
payloads. The first-read hook can paste a file's signature list in place of the
tool-name directive, ending any cut list with an explicit "list cut" line.
Tests: `hook_conformance.rs`.

### 6. Status carries the persisted resolution rate

`devmap status` and MCP `devmap_status` report the build's persisted
`resolution_rate`, including `by_language`, instead of recomputing it. A store
built before the field existed reports it as not measured, never as a rate of
zero, and a malformed value is an error. `coverage_gap_inventory.rs` pins that
a summary cannot claim a refusal the inventory does not name.

### 7. Gusset in CI, and `fanout.sh` on macOS

`.github/actions/setup-gusset` checks out the pinned Gusset revision and builds
the umbrella staticlib before any Go build, in `ci`, `rust`, `analysis-plane`
and `codeql`, and in `verify.sh` / `ci-local`. `rust/tools/fanout.sh` no
longer passes `-readonly`, which Apple's `/usr/bin/sqlite3` rejects on a WAL
store written by the bundled SQLite.

### 8. The release gate reads every lockfile and the release line

The 1.3.5 bump passed `scripts/check-release.mjs` although it was wrong twice
over: it regenerated `rust/Cargo.lock` but not `rust/gusset-engine/Cargo.lock`,
so every `cargo build --locked` of the umbrella failed, and it jumped the
version in every file at once, which a check that only compares the files with
each other cannot see. The gate now requires every workspace crate recorded in
any `Cargo.lock` under `rust/` to carry the product version, and the product
version to be the newest release in `docs/releases` or one step past it.
Notes outside the line carry `<!-- release: withdrawn -->`. Against the 71e2cf9
tree it fails on both counts.

`ci-local` also warns when the Gusset sibling is not at the revision
setup-gusset pins: the umbrella lock records that Gusset version, and a sibling
at another one fails `--locked` in a way that reads like a stale DevCouncil
lock.

### 9. An overridden base-class method is not dead

When a derived type overrides a base-type method, the base's implicit-receiver
call (`self.method()`) stays unresolved with the reason "implicit receiver
method is overridden by an indexed subtype". Liveness now records that call as
reaching the method, and the entry no longer vetoes the heritage exemption, so
the base method is not reported dead.

### 10. Console streaming buffer hardening (`devcouncil/console`)

Output chunking no longer overflows when computing a chunk's end near
`math.MaxInt`. An incomplete UTF-8 run carried across a window boundary is
bounded to at most one rune (`utf8.UTFMax - 1`); an oversized carry is flushed
before the next window.

### 11. Secret redaction in test failure assertions (`dc-verify`)

Verification test failure messages withhold credentials and tokens from the
stdout/stderr they print, so a failing run does not expose a secret in its log.

### 12. A Rust call written as a module path is a caller

`crate::resolver::Resolver::resolve_all()`, `crate::work::helper()`, a
file-level `super::helper()` whose parent module declares `helper`, and a
sibling crate spelled by its `use` name now bind when the module system can
place the path on exactly one indexed file. The receiver is not popped until a
file appears, and a `mod.rs` / `name.rs` pair, two crates with one name, or a
path that is also a child module abstains. Leading `super` segments inside an
inline module are spent the same way a `use` spends them, so
`super::Thing::build()` inside `mod tests` is `self::Thing`. Tests:
`rust_qualified_path_calls.rs`, `rust_qualified_super_calls.rs`.

### 13. Policy decisions go through the Gusset engine, and fail closed

`395af0db` routes the write-policy glob decisions through the Gusset engine
instead of Go's `fnmatch`. An engine that panicked, was poisoned, was closed or
answered malformed denies as a hard safety refusal; one that is merely *busy*
(past its deadline) answers with `fnmatch`, the reference the engine is held
equal to, and counts the fallback in `gussetfn.Fallbacks` (`63aa5e5c`), so a
slow pattern can no longer turn a soft "not allowed" into a non-demotable
`engine_unavailable`. The engine integration was hardened around it
(`fea3992f`, `876ace29`): `rust/gusset-engine/cgo-env.sh` folds the archive's
sha256 into the cgo flags so a Rust rebuild cannot be linked or test-replayed
stale, a poisoned handle is retired and reopened instead of failing every later
match, and the umbrella installs Gusset's counting allocator. The same merge
carries Windows and store hardening: native path validation, a shell-free
detached build, retries for sharing-violation and lost SQLite races on
read-only opens, and file-identity checks on Windows.

### 14. `devmap ask --evidence` / `devmap_ask_evidence`

For a behaviour whose name you do not know, `devmap ask --evidence "<question>"`
returns the ranked files with their source, the call edges between the hits and
the tests that reach them in one answer (`66cb226a`), served over MCP as
`devmap_ask_evidence` (`75bbf7d1`). A later round adds related tests and test
roles (`a1a5c3b8`), caps a page at 200 file reads with a fold-aware evidence
budget (`61de186d`), and makes `devmap_affected_tests` count runner-invoked
tests beside the code (`8e9669d6`). The language-server client's reads are
bounded and stdio writes can no longer wedge it (`37fd9beb`, with `e3bcb6b1`).

### 15. `impact` reports the call sites it could not bind

A caller the resolver could not bind is not an edge: it sits in the unresolved
ledger by name, and `impact` used to answer from edges alone. Flat and layered
`impact` (and MCP `devmap_impact`, which now also accepts `layers`) carry
`unresolved_namesakes`: ledger rows whose callee is the target's bare name,
kept to the target's language family, capped at 50 rows per name and 8 names,
with `truncated`, `names_not_checked` and `other_language_sites` disclosed
(`e9c5d11f`). When any exist or a cap bit, `walk_incomplete` says the edge list
is not the whole answer. They are candidates, not callers; `classification`
says why each was not bound. All names are read in one ledger pass at the
generation the walk used, and a generation pruned mid-query is reported rather
than mixed (`dd1e6909`). An ambiguous-name refusal now lists ids that work when
pasted back (`122759bd`), and the agent guide tells agents to read the field
(`81e029dd`).

### 16. Fewer unresolved callers: Go selectors and Python path loads

- **Go.** An unexported selector cannot leave its package, so `x.m()` on an
  untyped receiver binds to the package's one concrete method `m` as
  `SamePackage` (`5bab18f6`). It abstains on a second method, field, interface
  method, cgo `C.`, an external `_test` package, a test-only method seen from
  production, or a directory with a `.go` file DevMap did not read cleanly
  (`31a08d2d`). A partially parsed file vetoes only the names it spells
  (`0c07b7f3`).
- **Python loaded by file path.** `spec_from_file_location` / `module_from_spec`,
  `runpy.run_path`, `SourceFileLoader` and `imp.load_source` give the loaded
  file an import edge, resolved by path and never in the extractor
  (`5064372c`). Module-level path constants and same-file parameterised loaders
  are read (`ac4804f6`).
- **Python `sys.path` entries.** Module-level `sys.path.insert` / `append` /
  `[:0] =` entries with an anchored literal directory resolve imports ordinary
  resolution found nothing for (`823fd2eb`); an in-function insert, a
  class-body insert, or one that climbs above the repository root vetoes the
  imports it could redirect, so they abstain rather than link confidently
  (`5c33e532`). Ordinary resolution always wins and two entries holding the
  same module abstain.

### 17. Fewer false positives on the dead list

Template callees (`f<T>(x)`), the function an injected decorator parameter
hands to its caller, calls inside function-like `#define` bodies, and `T::m`
naming `T` no longer leave helpers reported dead at the confident tier
(`74419a09`, `b3a9edb1`; merged in `b97d0d38`). Measured on one GPU-kernel
repository: the dead list went from 112 rows to 64, none added. Extraction
schema 65 (`347dc7cc`).

### 18. Every module binding is a symbol

A Python module constant omitted from `__all__` had no node, so its importer
had no target and it had no blast radius. Every Python module-scope binding is
now a `Variable` (`__all__` decides only `is_exported`), type aliases are
emitted in Python, Rust and Go, each name of a multi-name Go spec and each name
a TS/JS destructuring pattern binds is a symbol, and Python and TS/JS import
names are read off the syntax tree instead of a string parser. The global call
rung no longer offers an interface or type alias as a bare-call target in
Rust, Python or TS/JS (`HWND(ptr)` had bound to `pub type HWND = isize`)
(`bb45211d`). Extraction schema 66.

### 19. The language policy ships as an always-on skill

`library/language-policy.md` is the eighteenth embedded skill: Rust or Go for
new code, Python only as a reference oracle or thin binding over a Rust core,
and the native UI language per platform, with a short pointer in each platform
skill (`24587cf3`).

### 20. A reader that loses a WAL sidecar is not refused as a security violation

`checked_sidecars` refused any SQLite sidecar whose link count was not 1 as
"has multiple hard links". A count of 0 is not an alias: SQLite deletes `-wal`
when the last writer closes, so a reader holding the sidecar open just before a
committing build removed it was refused. Only a count above 1 is the aliasing
the check exists to stop; 0 is now the ordinary missing-sidecar case
(`5fc38655`). Also in this range: CodeQL ignores `third_party`, so Gusset's
findings stay out of DevCouncil's (`f8f6086c`), and the unused
`build_with_resolutions` store entry point was removed (`0beb3d0e`).

### 21. A long-lived reader keeps its SQLite locks, names a damaged index, and refuses after a reinstall

`Store::open` and `open_read_only` opened the database and both WAL sidecars
through ordinary handles to check link counts, then closed them. Closing any
descriptor on a file drops every POSIX lock the process holds on it, so a
second open inside one process released the first connection's `-shm` read
lock, and another process's checkpoint could overwrite pages that reader's
snapshot still used. `safe_fs::inspect_regular` now checks the entry with
`fstatat` and holds no descriptor (`7cdd0249`); a test holding a snapshot
across a second open and a cross-process checkpoint failed before the fix and
passes now. One rare branch of `repair_sidecar_modes` still opens handles, and
the code says so.

Search over a damaged `nodes_fts` returned SQLite's "database disk image is
malformed". It is now refused with a message naming the index and
`devmap repair --fts`; `status` probes the index, so a damaged one reads as
degraded rather than fresh, and `repair_fts` recreates the table from its own
`sqlite_master` definition (`4cee6c50`). A `devmap mcp` server whose binary was
replaced on disk refuses tool calls with `binary_replaced` while `ping` still
answers (`c56bc198`); the commit reports 7 of 10 live servers on one machine
serving an old inode.

### 22. Builds without grammars report freshness, and their test builds are really grammar-free

GitPulse links `devmap-query` with `parse` off, and every `devmap_status` it
answered said `analyzer_freshness: null`. `PAYLOAD_GRAMMAR_IDENTITIES` now
commits the per-language identities a parsing build stamps, and a test fails
when the table and the compiled grammars disagree (`a2c2a397`).

`devmap-store` had `devmap-serve` as a dev-dependency, which turned `parse` back
on under `cargo test --no-default-features`, so no store test had ever run
without grammars. The three tests that needed `Daemon` moved to `devmap-serve`,
eleven fixture-parsing targets declare `required-features = ["parse"]`, and
`no_feature_off_crate_turns_parse_back_on_through_its_test_build` asks
`cargo tree` about every `FEATURE_OFF_SAFE` crate (`c6827858`). The write
path's `parse` gate now states its real reason, and the last ungated caller of
the unix-only `restriction_holds` is `#[cfg(unix)]`; a Windows-target check was
not run (`693cf687`).

### 23. Routes record their middleware, and the route views are MCP tools

`devmap routes` reported `middleware: null` on every route. A new `Registers`
edge kind runs from a route node to its middleware, and
`ExtractedRoute::middleware` has three states: `None` (no producer ran),
`Some([])` (a producer ran and found none), or the entries in run order.

- **Express:** earlier `X.use(...)` calls on the same receiver, and the
  arguments between the path and the handler.
- **Go:** routes are new — chi, gin, echo, gorilla/mux and net/http with Go 1.22
  patterns. A router-scoped `Use` covers only the routes after it in its block.

Middleware imported from outside the repository is ledgered `External` and
never binds to a same-named repository symbol (`7b2b78c4`). Route matchers use
ASCII word boundaries and Go scopes are scanned lazily, which the commit reports
brought builds back within noise and removed nine 0.4 dead false positives on
ScholarLM (`926d8540`). `devmap_routes`, `devmap_api_impact` and
`devmap_cypher` are MCP tools; `pdg` and `shape-check` stay CLI-only for
recorded reasons, and `no_missing_capability_is_a_served_tool` holds
`MISSING_CAPABILITIES` to the served tool list (`f3702af6`). This closes
`GAP-P7-DEVMAP-MCP-CLI`.

### 24. Rung floors and dead clusters over MCP, and session-report lists only open gaps

`devmap_dependencies`, `devmap_impact`, `devmap_trace` and `devmap_neighbors`
accept `min_rung` (the enum is read from `Rung::ALL`); an unknown, empty,
wrong-case or non-string rung is a tool error (`8239876a`). The dead tool's
output schema declares `dead_clusters`, `dead_clusters_truncated` and
`dead_clusters_incomplete`, which the payload already carried (`c42faed4`).
`session-report` takes the latest ledger line per `gap_id`, counts resolved
gaps instead of listing them, and reopens a gap recorded again (`4d205122`).

### 25. Rust calls bind through crate roots, re-exports, headers and binders

Three cross-crate shapes produced no edge: a bare crate root
(`dc_glob::matches`), a crate root that only `pub use`s the function, and a
`use`-imported submodule of a sibling crate. All three bind now (`7956cafd`);
the commit reports Rust unresolved sites on DevCouncil going from 118,633 to
118,051. A module imported from `super` is not the parent file (`2f20e99d`).

A Rust function's header is now its signature, and the resolver types
`T::f()?` and closure parameters from it (`e678a0e4`). A `MutexGuard` from
`.lock()?` or `Ok(guard)` types as the Mutex's `T`, and a loop variable over
`Vec<T>`, `[T]` or a set types as `T`; a block's binders are indexed once
(`6f76aed7`, schema bump `9814abb3`).

### 26. Python and Go receivers typed; re-export hops followed; precision measured

A Python parameter's annotation types its receiver (`876358b9`), and a Go
`var w T` types `w` (`8d08be0b`). A module-scope Python import is a re-export
hop, so a name an `__init__.py` lifts out of a submodule is no longer dead at
0.4, and a renaming re-export asks the terminal file for the name it declares
(`955fde8d`, `32e26307`). Two `#[cfg]` variants of one method are one dead row
(`8c5642d4`). `real_corpus_resolution.rs` labels 40 MarkDev call sites at a
pinned commit; the commit reports precision 19/20 and recall 19/21. It is
`#[ignore]`d and fails rather than passes when its root is unset (`8d95d027`).
Four more labelled fixtures were added (`cda54d14`).

### 27. Singletons, factory return values and a bare Go type name type their receivers

An imported module-scope instance (`export const svc = new Svc()`, Python
`service = Service()`) types its receiver, and a member of a value import is no
longer read as a module function (`992bf846`). `ExtractedSymbol.return_type`
records the type a callable's declaration writes, so `w := NewWorker()` and
`const svc = createService()` type their bindings; generics, `Promise<T>` and
optionals are refused, and a use reads the nearest assignment on every path to
it instead of the first one in the file (`f81a432c`, `9effb84c`). A Rust closure
reads the value captured at creation (`d4e0fbf0`). The commit reports +3471/−2
edges on ScholarLM. When two Go packages each declare `Client`, a bare `Client`
dispatches to the caller's own package, but only where the file wrote the type
bare and has no dot-import (`a313731e`).

### 28. Each walk reports the unresolved sites it touched, and call-blind files say so

`impact`, `trace`, `affected`, `explore`, `dependencies` and `ask --evidence`
attached one repository-wide sentence to every answer. Each walk now reads the
ledger only for the keys it reached and names a sorted sample; with no
generation or an unreadable ledger it falls back to the old sentence, and past
`MAX_RADIUS_LEDGER_KEYS` it says "only K of M" (`d8ae41f1`). A receiver call
whose method name no symbol carries (`mu.Unlock()`) cannot fill the per-key cap
and hide a real edge (`796cef82`). Store schema v24 re-adds
`idx_unresolved_rows_callee`, which `impact` reads through; the commit reports
p50 7.55 → 2.54 ms per call for 2.4 MB of index (`a284d14f`).

A bare Ruby send (`def entry; helper; end`) is a call, and `impact`/`trace`
refuse an empty answer for a symbol in a file a grammar read but no call
extractor covers (HCL, CFML) instead of reporting zero dependents
(`add97707`). A JSX tag is no longer a local binding of the component name, and
`useCallback`/`memo`/`forwardRef` wrappers bind a function (`0f9317d2`,
`c44ca3e9`).

### 29. `ask` ranks on the question, says when nothing answers it, and can be scoped

`ask` ordered its seeds by personalized PageRank alone, so a hub called by 40
handlers outranked the function whose name matched the question. The order is
now 0.7 normalized lexical score plus 0.3 normalized PageRank, and question
words no longer seed symbols (`7b513e8a`). A second lane's alternative blend
(`1293374c`) was dropped at merge; its `coverage_note` was kept: `ask` and
semantic `search` name query terms no indexed name or docstring contains and
label a head of single-term coincidences a weak match, but only when the head is
weak or those terms are at least half the question (`1b48ada5`). `ask`,
`ask_evidence` and semantic search accept `--path` and `--language`; a scope
that matches no indexed file is refused with what is there, and keyword search
refuses a scope (`d014dfbf`).

### 30. One devmap server per host, and a new worktree starts its own build

The plugin-version warning reads the active `installPath`, and the
duplicate-registration warning fires only when one host loads the same server
twice (`5e995aff`). `devmap integrate claude` stops writing a user-scope entry
beside the enabled plugin (`d490343f`), and `devcouncil integrate` stops
writing an unpinned `devmap` entry into `.cursor/mcp.json` and `.mcp.json` that
undid `devmap integrate`'s pinned one (`bdb101f2`). MCP queries carry the
host's session id, and `devmap hook user-prompt-submit` reminds a session that
has made no query, at most three times (`2f51f29e`); the commit reports 61 of 75
recorded sessions making none.

When a linked worktree's main checkout is indexed, SessionStart starts
`devmap build` in the worktree instead of only naming it (`4eec1ff5`). The
brief-storm test now allows a bare lane its own background build and asserts
that it is never briefed with the main checkout's counts (`ce55bdee`).

### 31. Stub detection reads the syntax tree, and the credential table is its own crate

`dc-verify`'s stub check was a per-line substring match. `stub_ast` parses
changed Rust, Go, Python and TypeScript files: proven placeholders block, empty
bodies are advisory, `skipped_test` and `assert_free_test` are new gates, and
`allow-stub: <reason>` moves a finding to `stub_allowed`. Unparsed files fall
back to the substring check, labelled derived (`c6b48a28`); the rigor gates are
claimed only when a file was parsed (`1502622d`), and on the substring path a
marker above a function covers its body (`f57bbaf5`). The commit reports a
44-case corpus with 0 false accepts and 0 false positives.

`dc-redact` is a new dependency-free crate holding the credential table split
out of `dc-verify`, which re-exports it unchanged, so GitPulse can vendor it
without `dc-verify`'s tree-sitter (`1a956bf8`, `a49cf985`). Manvi's `crates/`
workspace needs a `dc-redact` symlink and member to keep loading.

### 32. Verification dispatches criteria on their method and keeps every gap field

A requirement's `verification_method` was validated and then ignored.
`unit_test`, `integration_test` and `static_check` are discharged only when the
task's commands all passed; `manual` raises a hard
`unsupported_verification_method` gap; `llm_review` is refused at validation
(`b1b291fd`). Every gap field `verify` sets now round-trips to
`devcouncil_get_gaps` — requirement, criterion and method (`cb612c48`); file,
line and suggested command (`07b1700b`); stdout and stderr paths (`6f4ad99a`) —
and `gap-upsert` refuses a non-numeric `--line`. `--sandbox` accepts only
`local` (`c6c74f39`). A Lappi client was added, off by default and bounded, adding
at most one advisory gap per file (`17c7f75a`).

### 33. The Go host refuses malformed arguments, names only live commands, and judges every clause

Every Go MCP tool refuses an undeclared argument (`0ddadf0f`) and a declared one
of the wrong type or outside its enum (`0aa64ba9`).
`devcouncil_policy_check_write` judges the named task's scope and fails closed
on a missing store or unknown id (`20807010`, `e7574ce1`); with no gate it
answers `not_initialized` rather than `allowed: true`. Policy refusals, verifier
next actions and the packaged skills named Python-CLI commands that exit 2;
they now name commands the host dispatches, held there by tests that read the
dispatch table, and a project root that is relative, missing or carries an
unexpanded `$VAR` is refused (`5610f6e6`).

The policy ladder returned the first refused clause, so
`date; git push --force origin main` was allowed under the host posture. Every
clause is judged now, ordered hard > unreadable > soft > warn, and
`(cd ..; …)` and `builtin cd` are refused (`3728d0d2`). Redirects to
`/dev/null` and the other stream devices are not writes, and a `$(…)` keeps its
inner refusal's severity (`92569677`).

### 34. Task runs are per checkout and bounded, and briefs open with agent guidance

A second run anywhere in a repository was refused, so linked worktrees could
not run tasks in parallel. The slot is now the checkout (`checkout_busy`), and
`runs.reconcile` lets another host release a dead owner's attempt as
`outcome_uncertain` (`89e07f04`). `max_active_runs` is bounded to 1–64,
default 8 (`14b9e337`). Every task brief opens with a bounded

## Upgrade

The extraction schema moves from 58 to 72 across this release, so the next
`devmap build` re-parses every cached file once. Four lanes claimed numbers on
their own branches — resolver-precision 67, MCP parity 67, gap-audit 68,
factory return types 69 — and each was stamped on a payload carrying only that
lane's half. They were renumbered at merge so no two payloads share a number:
70 is gap-audit plus factory return types, 71 adds resolver precision, 72 adds
route middleware.

The store schema moves from 22 to 25. v23 and v25 write no DDL; they stamp
`user_version` so that a binary that does not know the language-server
resolution kinds (v23) or the `Registers` edge kind (v25) refuses the store
instead of misreading it. v24 re-adds `idx_unresolved_rows_callee`. The
`Registers` rung was written as v23 → v24 on its branch and renumbered at merge,
because main had already taken v24. The next `devmap build` migrates an older
store in place. After that, any earlier binary — including a build of the
first `v0.2.4` tag, and GitPulse's bundled devmap at schema 23 — refuses the
store and says to rebuild `devmap`.
