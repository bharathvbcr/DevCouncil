# DevCouncil v0.2.4 Release Notes

DevCouncil v0.2.4 and DevMap v0.2.4 are the same product version. The npm package,
the Go host (`devcouncil` / `dev`), and the Rust workspace (`devmap`, `dcstore`,
`dcverify`, `dcgrep`) all report **0.2.4**.

This release carries the work first stamped as **1.3.5** in 71e2cf9. That number
was a mistake — it was never a step in this release line — and it is withdrawn:
see [`v1.3.5.md`](v1.3.5.md). No GitHub Release was cut for it, but npm has
`devcouncil@1.3.5`; it is the same code as this release under the wrong number.

It adds an opt-in language-server pass to the resolver, a plain-language `ask`
query and a per-file `skeleton`, owners and test signal on `devmap blast`, and
richer write/first-read hooks. The store schema moves from **22** to **23**
(a version stamp only — see [Upgrade](#upgrade)). Sections 13–19 record what
the first draft left out: policy decisions on the Gusset engine, `ask --evidence`,
the unresolved-callers work, dead-list and module-binding extraction fixes, and
the language-policy skill.

## Highlights

### 1. Opt-in language-server edges: `devmap build --lsp`

`devmap-resolve` gains an `lsp` module (908 lines). With `--lsp`, the resolver
asks a language server on `PATH` about call sites that are *still in the
unresolved ledger* after the syntax pass, and may add two new resolution kinds,
`LanguageServer` and `LanguageServerDispatch`, when the server names a target
inside the repository.

It can only add. The syntax resolver still owns every deterministic and
unique-global claim, and a missing, hung, oversized or disagreeing answer never
falls through to a bare-name `UniqueGlobal`. The pass is bounded — 256 files,
90 s for the whole pass, 8 s per request, 256 KiB per JSON-RPC frame — and
anything past a bound is reported as *did-not-run*, not as zero edges. Without
`--lsp` the build is unchanged, and the build readout's `lsp` field is `null`
rather than an empty report. `build_lsp_opt_in.rs` and
`language_server_edges.rs` hold both halves.

Dead-code and liveness analysis treat `LanguageServerDispatch` like
`AmbiguousGlobal`: a dispatch edge is evidence something may be called, not
proof of which target is.

### 2. `devmap ask` / `devmap_ask`: plain-language find

`devmap search --semantic` ranks names only. `ask` answers a question about
behaviour: TF-IDF over symbol names plus docstrings seeds the search, then
personalized PageRank over stored call edges re-ranks it. Nothing new is
stored. Edges below the deterministic rung are excluded unless
`--min-confidence` lowers the floor, and a seed neighbourhood that is all
speculative comes back empty *with a withheld line*, not as a silent zero.
Served over MCP as `devmap_ask`. Tests: `ask_ranking.rs`,
`ambiguous_impact_seeds.rs`.

### 3. `devmap skeleton` / `devmap_skeleton`: a file's definitions without bodies

Signature plus span for every definition in one file. A definition whose
signature was not extracted still returns its span and says so, and an empty
file and a path the index does not contain are different envelopes
(`presence`). Truncation carries its metadata. Test: `skeleton_envelopes.rs`.

### 4. `devmap blast` names owners and test signal

`dc-regress` blast gains recent owners of each changed path (name and email
only) and a per-module test signal. Owners are collected from `git log` under
a shared 5 s deadline, 32 commits and 256 KiB of output per path, and include
the pre-image path of a rename. The test signal has a separate `unavailable`
state: a walk that could not finish, or a renamed test it could not reconcile,
never reads as "no tests". Tests: `owners_and_test_signal.rs`,
`change_to_impact.rs`.

### 5. Write and first-read hooks paste real context

The write hook now renders a short pre-edit blast for the symbols whose spans
contain the edited range, from the generation already on disk, labelled stale
when the index is not fresh and bounded by its own wall-clock and character
budgets; a missed budget is stated and the hook still exits 0. It reads edited
ranges from Cursor `afterFileEdit`, Claude Write/Edit and Codex `apply_patch`
payloads. The first-read hook can paste a file's signature list in place of the
tool-name directive, ending any cut list with an explicit "list cut" line.
Tests: `hook_conformance.rs`.

### 6. Status carries the persisted resolution rate

`devmap status` and MCP `devmap_status` report the build's persisted
`resolution_rate`, including `by_language`, instead of recomputing it. A store
built before the field existed reports it as not measured, never as a rate of
zero, and a malformed value is an error. `coverage_gap_inventory.rs` pins that
a summary cannot claim a refusal the inventory does not name.

### 7. Gusset in CI, and `fanout.sh` on macOS

`.github/actions/setup-gusset` checks out the pinned Gusset revision and builds
the umbrella staticlib before any Go build, in `ci`, `rust`, `analysis-plane`
and `codeql`, and in `verify.sh` / `ci-local`. `rust/tools/fanout.sh` no
longer passes `-readonly`, which Apple's `/usr/bin/sqlite3` rejects on a WAL
store written by the bundled SQLite.

### 8. The release gate reads every lockfile and the release line

The 1.3.5 bump passed `scripts/check-release.mjs` although it was wrong twice
over: it regenerated `rust/Cargo.lock` but not `rust/gusset-engine/Cargo.lock`,
so every `cargo build --locked` of the umbrella failed, and it jumped the
version in every file at once, which a check that only compares the files with
each other cannot see. The gate now requires every workspace crate recorded in
any `Cargo.lock` under `rust/` to carry the product version, and the product
version to be the newest release in `docs/releases` or one step past it.
Notes outside the line carry `<!-- release: withdrawn -->`. Against the 71e2cf9
tree it fails on both counts.

`ci-local` also warns when the Gusset sibling is not at the revision
setup-gusset pins: the umbrella lock records that Gusset version, and a sibling
at another one fails `--locked` in a way that reads like a stale DevCouncil
lock.

### 9. An overridden base-class method is not dead

When a derived type overrides a base-type method, the base's implicit-receiver
call (`self.method()`) stays unresolved with the reason "implicit receiver
method is overridden by an indexed subtype". Liveness now records that call as
reaching the method, and the entry no longer vetoes the heritage exemption, so
the base method is not reported dead.

### 10. Console streaming buffer hardening (`devcouncil/console`)

Output chunking no longer overflows when computing a chunk's end near
`math.MaxInt`. An incomplete UTF-8 run carried across a window boundary is
bounded to at most one rune (`utf8.UTFMax - 1`); an oversized carry is flushed
before the next window.

### 11. Secret redaction in test failure assertions (`dc-verify`)

Verification test failure messages withhold credentials and tokens from the
stdout/stderr they print, so a failing run does not expose a secret in its log.

### 12. A Rust call written as a module path is a caller

`crate::resolver::Resolver::resolve_all()`, `crate::work::helper()`, a
file-level `super::helper()` whose parent module declares `helper`, and a
sibling crate spelled by its `use` name now bind when the module system can
place the path on exactly one indexed file. The receiver is not popped until a
file appears, and a `mod.rs` / `name.rs` pair, two crates with one name, or a
path that is also a child module abstains. Leading `super` segments inside an
inline module are spent the same way a `use` spends them, so
`super::Thing::build()` inside `mod tests` is `self::Thing`. Tests:
`rust_qualified_path_calls.rs`, `rust_qualified_super_calls.rs`.

### 13. Policy decisions go through the Gusset engine, and fail closed

`395af0db` routes the write-policy glob decisions through the Gusset engine
instead of Go's `fnmatch`. An engine that panicked, was poisoned, was closed or
answered malformed denies as a hard safety refusal; one that is merely *busy*
(past its deadline) answers with `fnmatch`, the reference the engine is held
equal to, and counts the fallback in `gussetfn.Fallbacks` (`63aa5e5c`), so a
slow pattern can no longer turn a soft "not allowed" into a non-demotable
`engine_unavailable`. The engine integration was hardened around it
(`fea3992f`, `876ace29`): `rust/gusset-engine/cgo-env.sh` folds the archive's
sha256 into the cgo flags so a Rust rebuild cannot be linked or test-replayed
stale, a poisoned handle is retired and reopened instead of failing every later
match, and the umbrella installs Gusset's counting allocator. The same merge
carries Windows and store hardening: native path validation, a shell-free
detached build, retries for sharing-violation and lost SQLite races on
read-only opens, and file-identity checks on Windows.

### 14. `devmap ask --evidence` / `devmap_ask_evidence`

For a behaviour whose name you do not know, `devmap ask --evidence "<question>"`
returns the ranked files with their source, the call edges between the hits and
the tests that reach them in one answer (`66cb226a`), served over MCP as
`devmap_ask_evidence` (`75bbf7d1`). A later round adds related tests and test
roles (`a1a5c3b8`), caps a page at 200 file reads with a fold-aware evidence
budget (`61de186d`), and makes `devmap_affected_tests` count runner-invoked
tests beside the code (`8e9669d6`). The language-server client's reads are
bounded and stdio writes can no longer wedge it (`37fd9beb`, with `e3bcb6b1`).

### 15. `impact` reports the call sites it could not bind

A caller the resolver could not bind is not an edge: it sits in the unresolved
ledger by name, and `impact` used to answer from edges alone. Flat and layered
`impact` (and MCP `devmap_impact`, which now also accepts `layers`) carry
`unresolved_namesakes`: ledger rows whose callee is the target's bare name,
kept to the target's language family, capped at 50 rows per name and 8 names,
with `truncated`, `names_not_checked` and `other_language_sites` disclosed
(`e9c5d11f`). When any exist or a cap bit, `walk_incomplete` says the edge list
is not the whole answer. They are candidates, not callers; `classification`
says why each was not bound. All names are read in one ledger pass at the
generation the walk used, and a generation pruned mid-query is reported rather
than mixed (`dd1e6909`). An ambiguous-name refusal now lists ids that work when
pasted back (`122759bd`), and the agent guide tells agents to read the field
(`81e029dd`).

### 16. Fewer unresolved callers: Go selectors and Python path loads

- **Go.** An unexported selector cannot leave its package, so `x.m()` on an
  untyped receiver binds to the package's one concrete method `m` as
  `SamePackage` (`5bab18f6`). It abstains on a second method, field, interface
  method, cgo `C.`, an external `_test` package, a test-only method seen from
  production, or a directory with a `.go` file DevMap did not read cleanly
  (`31a08d2d`). A partially parsed file vetoes only the names it spells
  (`0c07b7f3`).
- **Python loaded by file path.** `spec_from_file_location` / `module_from_spec`,
  `runpy.run_path`, `SourceFileLoader` and `imp.load_source` give the loaded
  file an import edge, resolved by path and never in the extractor
  (`5064372c`). Module-level path constants and same-file parameterised loaders
  are read (`ac4804f6`).
- **Python `sys.path` entries.** Module-level `sys.path.insert` / `append` /
  `[:0] =` entries with an anchored literal directory resolve imports ordinary
  resolution found nothing for (`823fd2eb`); an in-function insert, a
  class-body insert, or one that climbs above the repository root vetoes the
  imports it could redirect, so they abstain rather than link confidently
  (`5c33e532`). Ordinary resolution always wins and two entries holding the
  same module abstain.

### 17. Fewer false positives on the dead list

Template callees (`f<T>(x)`), the function an injected decorator parameter
hands to its caller, calls inside function-like `#define` bodies, and `T::m`
naming `T` no longer leave helpers reported dead at the confident tier
(`74419a09`, `b3a9edb1`; merged in `b97d0d38`). Measured on one GPU-kernel
repository: the dead list went from 112 rows to 64, none added. Extraction
schema 65 (`347dc7cc`).

### 18. Every module binding is a symbol

A Python module constant omitted from `__all__` had no node, so its importer
had no target and it had no blast radius. Every Python module-scope binding is
now a `Variable` (`__all__` decides only `is_exported`), type aliases are
emitted in Python, Rust and Go, each name of a multi-name Go spec and each name
a TS/JS destructuring pattern binds is a symbol, and Python and TS/JS import
names are read off the syntax tree instead of a string parser. The global call
rung no longer offers an interface or type alias as a bare-call target in
Rust, Python or TS/JS (`HWND(ptr)` had bound to `pub type HWND = isize`)
(`bb45211d`). Extraction schema 66.

### 19. The language policy ships as an always-on skill

`library/language-policy.md` is the eighteenth embedded skill: Rust or Go for
new code, Python only as a reference oracle or thin binding over a Rust core,
and the native UI language per platform, with a short pointer in each platform
skill (`24587cf3`).

## Upgrade

The extraction schema moves from 58 to 66 across these changes, so the next
`devmap build` re-parses every cached file once.

The store schema moves from 22 to 23. The migration writes no DDL; it only
stamps `user_version`, so that an older binary that does not know the
language-server resolution kinds refuses the store instead of reading those
rows as neighbouring tiers. The next `devmap build` migrates a v22 store in
place. After that, a v0.2.3 binary refuses the store and says to rebuild
`devmap`.

## Verification

Run on Linux (x86_64), Rust 1.98.1, Go 1.26.6, with the Gusset sibling at the
revision setup-gusset pins (7a56c3c):

- `node scripts/check-release.mjs`: `OK: product version 0.2.4 is consistent`.
- `npm run test:scripts`: 79 passed, 0 failed.
- `cargo metadata --locked` in `rust/` and in `rust/gusset-engine/`: both pass.
- `cargo build --release --locked -p devmap-cli` and
  `cargo build --release --locked` in `rust/gusset-engine`: both build.
- `go test ./gussetfn` passes and `go run ./cmd/devcouncil gusset-check`
  prints `gusset-check: ok`.
- `go test ./cmd/devcouncil/... ./devcouncil/mcp/ ./policy/`: pass.

### What is not verified here

The full `rust/verify.sh` gate and the Rust workspace test suite were not run
for this release, nor anything on macOS or Windows. `gofmt -l` flags
`policy/zfix_split_test.go`, as it did before this release.

Sections 13–19 were written from the commit messages and diffs in
`32dfd0c0..v0.2.4`; the verification list above predates them and does not
cover their tests, and the measurements they quote (the 112 → 64 dead-list
drop, the Go selector counts) are the commits' own, not re-measured for these
notes.
