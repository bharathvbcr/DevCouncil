# DevCouncil v1.3.5 Release Notes

DevCouncil v1.3.5 and DevMap v1.3.5 are the same product version. The npm package,
the Go host (`devcouncil` / `dev`), and the Rust workspace (`devmap`, `dcstore`,
`dcverify`, `dcgrep`) all report **1.3.5**.

This is a major feature release that adds LSP-backed resolution, natural-language
query support, expanded blast-radius analysis, and strengthened MCP protocol
conformance. It spans 46 files across 9 crates with over 3,000 lines of new
functionality and tests.

## Highlights

### 1. LSP-backed symbol resolution (`devmap-resolve`)

A new `lsp` module allows the resolver to supplement tree-sitter edges with
Language Server Protocol responses, improving accuracy for implicit receiver
dispatch and cross-module call sites that tree-sitter grammars cannot see.
Resolution honesty and audit regression tests are extended to cover the new
edges.

### 2. Natural-language query engine (`devmap-query`)

The `ask` module adds a ranked, natural-language interface to the code graph.
Ambiguous impact seeds are handled explicitly, and skeleton envelopes carry
truncation metadata so callers know when results are incomplete. New tests
cover ranking, ambiguous seeds, and envelope completeness.

### 3. Expanded blast-radius and regression analysis (`dc-regress`)

The blast module gains owner-aware test-signal propagation: when a change
touches a symbol, the graph now walks outward through ownership edges as well
as call edges, surfacing tests that cover the changed region through indirect
ownership. History analysis is refined with paired timing.

### 4. Git-hook hardening (`devmap-cli`)

The hook subsystem receives 647 lines of new conformance logic and tests,
ensuring that `devmap` post-commit and post-checkout hooks validate arguments,
handle concurrent invocations, and degrade gracefully when the store is locked
or the index is stale.

### 5. MCP server protocol hardening (`devmap-serve`)

Adversarial and spec-conformance test suites are expanded. The protocol module
gains 121 lines of additional request-validation logic, and the MCP handler
adds stricter envelope checks for malformed tool calls.

### 6. Store schema and edge-index improvements (`devmap-store`)

The store gains corruption-detection logic (`a_corrupt_analysis_is_not_an_absent_one`)
and a coverage-gap inventory test, ensuring that a corrupt analysis row is never
silently treated as missing. The migration ladder and edge index are tightened.

### 7. Dead-code and liveness analysis improvements (`devmap-analyze`)

Dead-cluster detection and liveness analysis are refined for resolution-rate
awareness: clusters whose members are all below the resolution threshold are
no longer reported as dead, reducing false positives in polyglot repositories.

### 8. CLI presentation and build-target validation (`devmap-cli`)

The CLI's `main.rs` gains 395 lines of new subcommand and output logic. A new
test asserts that every test target declares its grammar need, and the blast
test suite verifies that blast names what a change reaches. LSP opt-in is
gated by a build flag with a dedicated test.

## Compatibility

- **Store schema**: unchanged from v0.2.3 (schema 22). No migration required.
- **Node.js**: >=18 (unchanged).
- **Rust**: 1.89+ (unchanged).
- **Go**: 1.21+ (unchanged).

## Install

```sh
bash scripts/install.sh
```

Or standalone DevMap only:

```sh
bash scripts/install.sh --only=devmap
```
