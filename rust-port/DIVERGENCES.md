# devmap (Rust) vs Python Baseline Divergence Ledger (R3)

This document tracks deliberate, documented divergences between Python `devcouncil.indexing` / `codeintel` behavior and `devmap` (Rust).

| Finding ID | Python Behavior | devmap (Rust) Behavior | Justification / Test |
|------------|-----------------|------------------------|----------------------|
| **G1** | CFG entry/exit threading missing | Explicit entry/exit control flow nodes | Correct PDG graph contract |
| **G2** | Leader line attribution inaccurate | Blocks own leader lines explicitly | AST block ownership accuracy |
| **G3** | Python stdlib names resolve globally | Stdlib name guard restricted to unique-global rung within Python family | Prevents stdlib name pollution across languages |
| **G4** / **G26** | Nondeterministic hash map iteration | Deterministic output (`BTreeMap`/`BTreeSet` / sorted emission) | R4 requirement: byte-identical artifacts across builds |
| **G5** | Multi-candidate pick emitted as `Extracted` | Multi-candidate pick MUST NOT emit `Extracted` confidence | R5 requirement: confidence honesty |
| **G6** | Import-scoped resolution silently widens | Strict import-scoped resolution | Prevents false-positive edge creation |
| **G7** | Ambiguous inheritance resolution guesses single path | Ambiguity fans out or abstains with `Unresolved` | R5 requirement: confidence honesty |
| **X1** | Misses TS `enum`/`namespace`/`declare`/`abstract`/overloads | Parses TS syntactic constructs cleanly | Parity requirement for TS AST |
| **X2** | Drops `new_expression` and Go `composite_literal` calls | Extracts `new` calls & composite literal references | Complete call-graph extraction |
| **X3** | Ignores `export *` re-exports | Emits re-export chain sentinel for `export *` | Full export graph tracking |
| **X9** | Drops grouped `use` statements in Rust | Expands grouped Rust `use {a, b::c}` statements | Complete import resolution for Rust |
| **G19** | Generic impl blocks fail resolution | Handles generic impl resolution (`impl<T> Trait for Struct<T>`) | Rust trait resolution parity |
| **X30** | Solidity functions emitted flat (`Contract.sol::get`) | Owned by their contract (`Contract.sol::SimpleStorage.get`) | Same ownership rule devmap applies to Java/C# methods; the baseline loses the owner. `treesitter.rs` generic extractor |
| **X31** | Exported module-level bindings emitted as kind `function` | Emitted as `Variable` (`f.go::Limit`, `c.ts::VALUE`) | Python's kind is a misclassification; devmap records the correct kind. Only *exported* bindings, so private locals add no dead-code noise. `exported_module_level_bindings_are_symbols` |
| **X32** | HCL/Terraform parsed by the generic extractor, blocks not addressable | Blocks emitted under their Terraform address (`resource.aws_s3_bucket.b`) | Matches the identity `terraform plan` prints and operators already use. `terraform_blocks_are_symbols_with_terraform_addresses` |
| **X16** | Arbitrary 500-symbol cap on snapshots | Budgeted truncation with shown/total flags | `devmap-query/snapshots.rs` test_x16 |
| **X18** | Regex-based public symbol rules | Per-language public rules in snapshot builder | `devmap-query/snapshots.rs` test_x18 |
| **V14** | Artifact writes without atomic rename | tmp+rename with fingerprint skip | `devmap-query/artifacts.rs` test_v14 |
| **G8** | Fixed traversal depth | Parametric depth in shared kernel + query impact/trace | `test_findings_suite.rs` test_g8 |
| **B3** | Full rewrite on small edits | Differential generation write with affected_paths | `test_findings_suite.rs` test_b3 |
| **T1** | Unbounded manifest | ≤2k-token manifest with subsystem cap | `test_findings_suite.rs` test_t1 |
| **V12** | Dead list hides total count | Budgeted dead with shown+hidden=total | `test_findings_suite.rs` test_v12 |
| **X14** | Empty list for unknown dependents | Structured zero-count unavailable semantics | `test_findings_suite.rs` test_x14 |
| **G10** | PDG batch reads unoptimized | Extraction cache enables shard re-read | `test_findings_suite.rs` test_g10 |
| **N7** | RRF/vector ranking | FTS + lexical rank only (RRF deferred) | `test_findings_suite.rs` test_n7_rrf |
| **LSP (X11–X13)** | Python LSP adjunct live | **Cut** — no production MCP/CLI usage grep hits; Phase 7 documents cut | STATUS.md Open Questions |
| **SC11** / **SC6b** | `impl Trait for Type` methods are qualified by the **trait**, and a trait's bare method signatures are not extracted at all | Impl methods are qualified by their **type**; the trait's declared signatures are extracted and own the `Trait.method` identity | A qualified name is the graph's join key. Under the Python naming every implementor of a trait shares one identity — a single `impl` overriding a defaulted method already produced `Trait.method` twice, so two nodes existed that no edge could distinguish. Correctness of the join key outranks bug-for-bug parity. Costs 1 net parity diff on `rust_app` (18 → 19), where the same dead symbol is reported under a different name. `symbol_identities_are_unique_within_a_file`; `test_wiring_exemptions` asserts BOTH the declaration and the implementation stay exempt |
| **X6** / **X7** | Regex recovery can fabricate symbols from syntactically invalid source | Tree-sitter error trees remain `Partial`; regex recovery is not promoted to authoritative extraction, and error-overlapping symbols are excluded from dead-code conclusions | `test_treesitter_extraction`; `test_x6_partial_error_range_symbol_is_exempt` |
| **SC6** | Entry-point exemption is file-scoped only: one `func init()` exempts the *whole file* (`indexing/wiring.py` `content_liveness_exemption` → `"side_effect"`), and Rust/Go/pytest entry points other than React lifecycle methods have no rule at all | Entry points are exempted **per symbol** via `WiringAnnotation.target_symbol`. A `func init()` exempts `init` and nothing else, so ordinary unused functions beside it stay confidently dead | `test_hardening.rs` `test_runtime_entry_points_are_exempt_without_exempting_their_file`; `test_phase3_analysis.rs` `symbol_scoped_exemption_reports_its_own_reason_not_the_files` |
| **X33** | `.proto` carries no symbols; the extension appears only as a path-substring hint for the `models` subsystem bucket (`repo_mapper.py:1015`) | Discovered as `protobuf` and tier-2 recovered: `message` / `service` / `rpc` become symbols | Discovery, not extraction, was the defect — `is_indexable_source` admits only extensions `detect_language` names, so 19 `.proto` files on one corpus never reached an extractor to be counted as missing. `grammarless_source_languages_are_still_discovered` |
| **X34** | `.ps1` is role-classified as a script (`repo_mapper.py:854`); no symbols extracted | Discovered as `powershell` and tier-2 recovered: `function` declarations become symbols | Same discovery gap as X33. 17 `.ps1`/`.psm1`/`.psd1` on the same corpus; 9 recover declarations, 8 genuinely declare none. Verified against `git ls-files`, not against the indexer's own view |
| **X35** | `.ipynb` is not referenced anywhere in the Python indexer | Notebooks extracted; symbols relocated from the reconstructed code buffer back into the raw JSON so spans index the file on disk | A span into a reconstructed buffer points at bytes that do not exist in the file a reader opens. `notebook.rs` |
| **X36** | A file whose language has no grammar contributes nothing | Contributes a `File` node, plus any tier-2 symbols | The `File` node was previously pushed only on the tree-sitter path, so a grammarless file was recorded in `generation_files` and absent from the graph — unable to be an edge target or answer a file-level query. Changes node counts against the Python baseline by one node per grammarless file |
| **X37** | The portable fallback extractor's output is indistinguishable from parsed output | Tier-2 output is labelled `ParseOutcome::Fallback` / `ExtractionEngine::RegexFallback` on every file, and prose/data languages are denylisted from scanning entirely | A pattern-matched symbol and a parsed one are different claims. Unlabelled, the tier attributed Go and TypeScript types written inside fenced code blocks in design documents to the `.md` files describing them — 40 files, 457 symbols that exist nowhere. `NON_DECLARATIVE_LANGUAGES`, `prose_and_data_formats_are_not_scanned` |
| **X38** | `LanguageSpec.embedded` is declared and read by nothing; a `.svelte` / `.vue` / `.astro` / `.liquid` file is parsed by its outer grammar only, and the entire `<script>` body is one opaque leaf — measured recovery on all four: 1 symbol (the `File` node), 0 imports, 0 calls, reported `Clean` | Embedded script regions are located, routed to the language `embedded` permits, and merged with every span shifted into the outer file's byte coordinates. Vue additionally permits `tsx`, which the frozen list does not name | A `Clean` outcome over a file whose code half was never read is the worst shape available: it is indistinguishable from a file that genuinely declares nothing. The `tsx` addition is Vue-only because Vue's compiler accepts `<script lang="tsx">` while Svelte's template is not JSX and an Astro `<script>` is plain JS/TS — permitting it there would parse a region under a grammar its framework never compiles it with. Python never read `embedded`, so its list records no decision about TSX to diverge *from*. `embedded_scripts.rs` (15 tests, 11 red against the pre-fix code); the divergence is declared by name in `test_x8_language_authority_matches_frozen_python_registry` so an undeclared change to any other `embedded` list still fails |
| **X39** (PLAN.md §3 `G6`) | `code_graph.json` is the only encoding; every consumer reads it, and on a 3,674-file corpus it is 84,276,217 B (~21M tokens) | A second *encoding* of the same model is written beside it on request (`devmap manifest --compact-graph-output`). Each distinct string is written once and referred to by index | **The verbose artifact stays canonical** and is written either way — this is additive, and no existing consumer changes. Measured on this repository by the Rust encoder: 21,186,034 B -> 5,001,998 B (**-76.4%, 4.24x**); `json.loads` 85.2 ms -> 46.2 ms (median of 5). `source` + `target` alone were 52.6% of the verbose file: 14,324 distinct endpoint strings written 147,726 times. Both encodings render from one `build_code_graph_value` traversal, so a dropped field is impossible by construction; `decode_compact(encode_compact(v)) == v` is the test, red-demonstrated by making the encoder skip one column. A table whose rows are not uniformly shaped is carried verbatim and named in `verbatim_tables` rather than interned against a spec taken from the first row. **It does not make the graph agent-readable** — 5.3M tokens to 1.25M is still unopenable; it buys bytes, parse time and disk churn, and `devmap search`/`impact`/`trace` remain the way to read the graph. Numbered `X39` here because this table's `G6` (row above) is the audit's "import-scoped resolution silently widens" — the two documents number independently and the collision is real, not a typo. `PLAN.md`'s G6 row records a columnar form as "measured and declined": that decision was about `repo_map.json`, whose `files`/`dependents` shape `CLAUDE.md` documents to agents as the navigation contract, and it does not apply here. `code_graph.rs` tests + `test_code_graph_artifact.rs::the_interned_graph_is_opt_in_and_decodes_to_the_verbose_one` |

## Baseline regeneration decisions

- **2026-08-12 — canonical snapshot schema repair:** regenerate all Phase 1 golden snapshots after fixing the snapshotter to emit PLAN §7.8 identities (`node.id/kind/path/line/name/exported`, `edge.source/target/kind/confidence`, `dead.id/confidence`). The prior files silently wrote empty `qualified_name`/`span` fields that do not exist on the frozen graph schema and therefore were not a usable parity baseline. `tools/snapshot/test_generate_snapshots.py` proves graph-build failures cannot be rewritten as authoritative empty snapshots.
| **K5** | Every file the Python engine could not parse counted as a parse failure, prose and data formats included | A format with no grammar (`.md`, `.json`, `.toml`, …) contributes a `File` node and is `ExtractionEngine::NotApplicable`, not a parse failure; a malformed file of a grammar language still is | `parse_failed` in `build_history` and status now means "a source the kernel should have parsed and could not". Tests `k5_prose_formats_are_not_parse_failures_but_broken_files_still_are`, `k5_build_history_parse_failed_excludes_grammarless_prose` |
| **K7** | The Python walker skipped generated directories by name only (`target`, `node_modules`, …) | Any directory carrying a `CACHEDIR.TAG` with the standard signature is skipped by discovery, by `--affected`, and by the watcher's enqueue — in addition to the name list | Measured: 1,041 of 2,363 indexed files on DevCouncil were cargo output under untracked `target-*` dirs. Tests `k7_a_cachedir_tagged_directory_is_never_walked_or_indexed`, `k7_watcher_events_inside_a_cache_directory_are_never_enqueued`, `k7_a_cachedir_tag_without_the_signature_is_not_a_cache_directory` |
| **SEAM-1** | One `dev map` committed one Python generation and wrote the agent guides afterwards, so the store never knew `AGENTS.md`/`CLAUDE.md` until the next build | A repository whose guides a build creates or changes gets a second, incremental kernel build for those files; a repository that already carries them commits exactly one generation | Store, artifacts and freshness stamps describe the same tree. Tests `test_full_map_commits_one_generation_and_records_progress`, `test_map_artifacts_reuses_generation_when_nothing_changed` |
| **SEAM-2** | A failed Python build could stamp a lean, `graph_degraded` map over a healthy generation | A failed or timed-out kernel build raises `DevMapEngineError` (with a diagnosis code) and leaves the prior artifacts byte-identical; there is no lean map | Tests `test_map_artifacts_propagates_a_kernel_failure_without_writing_a_map`, `test_map_artifacts_keeps_the_prior_artifacts_when_the_kernel_times_out` |
| **Q1 — `explore` ranking** | `CodeIntelQueryEngine.explore` built its match list as `exact + partial` and then sliced `[:limit]`. Within each half the order was whatever the store yielded, so which definitions a capped answer kept depended on node order, not relevance | FTS hits are scored (exact 1.0 / prefix 0.95 / other 0.8, the same `name_match_score` `search` uses) and sorted before any cut; the cut is the token budgeter's, and `definitions.total` is the index-wide match count from `count_search_symbols` | R7: rank before truncate, and never report a page's length as a total. `explore_and_affected.rs` `one_definition_is_the_highest_ranked_one_not_the_first_row`, `a_capped_definition_list_carries_the_total_it_was_capped_from` |
| **Q2 — `explore` snippets** | `_snippet` returned `""` for a file it could not open and `""` for a symbol whose span was empty | An unreadable file yields `source: ""` **plus** `source_unavailable_reason`, and `span: (0, 0)` rather than a line range nobody computed. A span capped to fit the budget reports `source_omitted_bytes` | Class A: a check that could not run must not report what a check that ran and passed reports. `an_unreadable_source_file_reports_why_instead_of_an_empty_snippet` |
| **Q3 — `explore` edge lists** | A fixed `_EDGE_SAMPLE = 50` slice per direction, with `<side>_total` and `<side>_truncated` beside it | Each direction is a whole `Response` with its own `shown`/`hidden`/`total`/`truncated`/`tokens_used`/`resolution`/`walk_incomplete`, funded from a published share of one budget (`ExploreBudget`). A direction that could not be walked is `Unavailable`, not empty | The count stays exact whatever the budget buys, so "0 shown of 42 callers" can never read as "no callers"; and a walk that could not run is distinguishable from one that found nothing |
| **Q4 — blast radius** | Layers carried `{depth, nodes, confidence, count}` with `confidence` defaulting to the string `"extracted"` for an empty band | Layers carry the *measured* lowest confidence as a float (`None` for an empty band), the exact `node_count` beside a `BLAST_LAYER_NODE_SAMPLE`-capped `nodes` list with `nodes_omitted`, plus `unmatched_targets` and `walk_incomplete` | A default of `"extracted"` on a band with no edges is invented evidence. `a_depth_capped_radius_reports_that_it_is_a_lower_bound` |
| **Q5 — `affected_tests` test detection** | `_is_test_path` asked `"/test" in "/" + path.lower()`, so `src/testing_utils.py`, `lib/latest/mod.rs` and `app/protester/main.go` were tests | `is_test_path` requires a directory segment that *is* a test directory (`test`, `tests`, `spec`, `specs`, `__tests__`, `testing`, `e2e`) or a file name carrying a test affix (`test_`/`spec_` prefix, `.test.`/`.spec.`/`_test.`/`_spec.`/`-test.`/`-spec.` infix, a bare `test`/`spec` stem, or a camel-case `…Test`/`…Spec` stem) | The affected-test list gets shorter; everything that leaves it was never a test. `test_path_detection_matches_directories_and_affixes_not_substrings`. Measured on this repository for `budget_take`, both engines returned the **identical** 11 test files |
| **Q6 — `affected_tests` ordering and unmatched targets** | Sorted alphabetically, uncapped, and a target that matched nothing contributed no seeds and no signal — a typo came back as "no affected tests" | Ranked nearest-first (`depth` from the banded walk) before the budgeter cuts, each row carrying its distance and the symbols the walk reached; targets that matched no traversal start are named in `blast_radius.unmatched_targets`, and a radius with no seed at all is `Unavailable` | "No affected tests" is the costliest possible false negative. `affected_tests_are_ranked_by_distance_before_they_are_truncated`, `a_target_that_matches_nothing_is_reported_rather_than_answered_as_zero` |
| **Q7 — runtime-observed liveness** | `CodeIntelQueryEngine.dead` merged fingerprint-matched runtime observations and suppressed dead candidates they proved live, reporting `runtime_proven_live` | **Not ported.** The kernel's `dead_symbols` does not consult runtime observations, so a symbol a debug session proved live is still listed as a dead candidate | Retired, not replaced. `dead()` had no production caller before the deletion — MCP `devcouncil_code_dead` and `dev graph dead` both answer from the kernel — so the suppression was unreachable outside its own test. The observation **merge** survives at `CodeIntelService.load_with_runtime_observations`, which `run_cypher` reads, and is pinned by `test_matching_runtime_observation_becomes_a_graph_edge` |
| **Q8 — `dev graph search` fallback** | With no devmap index, plain search fell through to `CodeIntelQueryEngine.search`, whose `total` was `None` because the store applied the limit inside SQL | Kernel-only, and an unbuilt index exits 3 with a message naming which search was asked for. The kernel measures the match set with `count_search_symbols`, so a capped page reports a real total | The Python fallback could not run anyway: nothing has written `.devcouncil/codeintel/index.sqlite` since the Python writer was retired. `test_search_capped_rows_are_not_reported_as_complete` |
