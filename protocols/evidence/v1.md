# Acceptance evidence protocol v1

The canonical protocol specification is [dc-evidence/PROTOCOL.md](../../rust/dc-evidence/PROTOCOL.md). The exact-byte compatibility fixtures are [fixtures/v1](../../rust/dc-evidence/fixtures/v1); Rust library and CLI tests execute those same files.

This additive protocol is advertised independently of `dcverify health.schema_version=1`. Existing source-diff `dcverify check` behavior is unchanged. Evaluation completion (`ok`) is separate from acceptance (`passed`, `failed`, or `incomplete`).

Implementations must preserve the independent expected contract/capability hashes, run/session/admission epoch identity, ordered epoch transitions, immutable artifact bytes and completeness semantics described in the canonical specification. Schema version remains `1` with additive bundle fields (`outcome`, `policy_sha256`, `interventions`, `human_actions`, `recoveries`, `locator_hits`) and reserved contract facts (`outcome.id`, `outcome.kind`, `human_control_returned`). Imported bundle checks establish consistency over supplied evidence, not trustworthy observation by an untrusted producer.
