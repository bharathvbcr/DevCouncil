### The false-accept corpus.
###
### Every gate in this crate is a classifier, and until this file existed none
### of them had a measured error rate. The suites beside it prove that a gate
### fires on the input it was written for; none of them could say how often it
### fires on input it was not, or how often it stays quiet on input it should
### catch. "dcverify passed" was therefore a claim with no denominator.
###
### This is reverify's move, aimed at a diff instead of a binary: known-true and
### known-false cases on the same corpus, a confusion matrix, and a build that
### fails on a single false accept. `tests/false_accept.rs` runs it.
###
### FORMAT
###
### A case begins at a line starting `### case:` and runs to the next one. The
### header lines that follow declare what EVERY gate must say about it, not only
### the gate the case was written for — so a fixture aimed at `secret_scan` is
### also a standing negative control for `stub_detection`, and a gate that
### starts firing everywhere is caught by the cases it has nothing to do with.
### A diff body line never starts at column 0 with `###`, so the separator is
### unambiguous.
###
###   secret_scan, stub_detection, stub_allowed, assert_free_test,
###   skipped_test:  blocking | advisory | clean
###     blocking  at least one blocking finding from that gate
###     advisory  at least one advisory finding and no blocking one
###     clean     no finding at all, at any severity
###
### stub_detection, stub_allowed, assert_free_test and skipped_test all come
### from detect_stubs. The harness has no working tree, so a file the diff adds
### whole (`--- /dev/null`, lines from 1) is parsed by stub_ast and every other
### file falls back to the substring checks. The AST cases below are therefore
### new-file diffs, and several are chosen because the two paths disagree on
### them: a placeholder inside a string literal, an empty body, an abstract
### method. stub_allowed is where a finding lands when an `allow-stub: <reason>`
### marker covers it.
###
###   substance:  low | substantive | unjudged
###     low          judged, and under the informativeness threshold
###     substantive  judged, and over it
###     unjudged     fewer added lines than MIN_LINES_TO_JUDGE
###
### Every credential below is a published example, a documented placeholder, or
### a literal run of `A`. None has ever authenticated anything. A case needs the
### SHAPE of a credential, and a real one would make this file the leak the gate
### exists to prevent.

+pub fn classify_scope(files: &[FileDiff], planned: &[String]) -> Scope {
+    let mut scope = Scope::default();
+    for file in files {
+        if planned.iter().any(|p| p == &file.path) {
+            scope.in_scope.push(file.path.clone());
+        } else {
+            scope.orphans.push(file.path.clone());
+        }
+    }
+    for plan in planned {
+        if !files.iter().any(|f| &f.path == plan) {
+            scope.untouched_planned.push(plan.clone());
+        }
+    }
+    scope.in_scope.sort();
+    scope.orphans.sort();
+    scope.untouched_planned.sort();
+    scope
+}

+/// Bounds how long one verification pass may run.
+pub struct Budget {
+    deadline: Instant,
+    spent: Duration,
+}
+
+impl Budget {
+    pub fn starting_now(limit: Duration) -> Self {
+        Budget { deadline: Instant::now() + limit, spent: Duration::ZERO }
+    }
+
+    pub fn remaining(&self) -> Duration {
+        self.deadline.saturating_duration_since(Instant::now())
+    }
+
+    pub fn charge(&mut self, cost: Duration) -> Result<(), Exhausted> {
+        self.spent += cost;
+        if self.remaining().is_zero() {
+            return Err(Exhausted { spent: self.spent });
+        }
+        Ok(())
+    }
+}
+
+pub struct Exhausted {
+    pub spent: Duration,
+}
