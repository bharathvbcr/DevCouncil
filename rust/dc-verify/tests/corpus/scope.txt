### The scope corpus: `classify_scope` measured as a classifier.
###
### The unit tests in src/lib.rs show the classifier on inputs chosen to
### pass. This file gives it a denominator. Every path a case's change touches
### is labelled by hand, and `tests/classifier_corpus.rs` reports precision and
### recall over those labels. The numbers in rust/STATUS.md come from here.
###
### LABELLING RULE (applied by hand, before the classifier was run)
###
###   orphan    the change adds, modifies, deletes, renames away from, or
###             changes the mode of this path, and no planned entry names it
###   in        some planned entry names it, as a literal path or as an
###             fnmatch pattern in the Python dialect `classify_scope` documents
###             (`*` crosses `/`), after `./` and `\` normalisation on both sides
###
### A path an entry names is the same file however the plan spells it: `./a`,
### `a` and `a` with Windows separators are one file. A rename touches two
### paths, and the one it renames away from is changed too: its content left it.
###
### FORMAT
###
### `### case: <name>` opens a case. Header lines that follow:
###   `### planned: <entry>`    one per planned entry (zero is allowed)
###   `### orphan: <path>`      a path the gate must report as an orphan
###   `### in: <path>`          a path the gate must not report as an orphan
###   `### note: <text>`        free text
### The diff follows. A path the gate reports that the case does not label
### fails the run: an unlabelled output is not a measurement.
