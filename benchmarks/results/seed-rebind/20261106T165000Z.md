# Seed rebind: what staging a donor store writes (criterion 3, card ft-983bd7bc)

Bench: `rust/devmap-store/examples/seed_rebind_bench.rs`
(`seed_rebind_bench <src.sqlite> <worktree_root> <mode> <out_dir>`), built `--release`.
Each run stages a clone of the source (`stage_seed_healing_wal`), rebinds it for the mode, and
settles it (`settle_staged`).

## Scale (state it before reading any number)

* Source: a `VACUUM INTO` private copy of this repository's DevMap store, 188,383,232 bytes
  (46,641 pages of 4,096 bytes), **2 generations** (`generations_rows` = 2).
  Never the live store.
* Filesystem: APFS; every run reports `seed_method: Clone` (clonefile), so
  `pages_changed` is the copy-on-write write amplification.
* Method: 5 runs per mode, interleaved (full, latest, firstbuild, repeat), min and spread of 5.
  `instructions retired` from `/usr/bin/time -l`. The machine was shared (load 12-20), so wall time
  is noisy and is reported for completeness only; instructions retired and `pages_changed`
  (deterministic) are the evidence.
* With only 2 generations the "rewrite every row" cost is small. This is **not** a 15 ms claim:
  a store with many retained generations rewrites proportionally more pages in `full` and
  `firstbuild`; that was not measured here.

## Modes

* `full` (before): the pre-81b1372e rebind, `UPDATE generations SET repo_root` on all rows plus `pending_state`.
* `latest` (after): current `rebind_staged` (latest row, `seed_rebind`, `pending_state`).
* `firstbuild`: `latest`, then the normalisation the first build/restamp runs
  (`Store::restamp_latest_head` -> `clear_seed_rebind_and_normalize_generations`): the deferred cost.

## Results

| mode | pages_changed (of 46,641) | bytes changed | instructions retired, min (spread of 5) | rebind phase ms | normalize phase ms | wall s (min-max) |
| --- | --- | --- | --- | --- | --- | --- |
| full | 1,295 | 5.30 MB | 878,085,150 (878.1M-938.9M) | 33.3-72.0 | n/a | 0.10-0.22 |
| latest | 648 | 2.65 MB | 755,565,674 (755.6M-759.3M) | 7.1-26.0 | n/a | 0.07-0.10 |
| firstbuild | 1,295 | 5.30 MB | 1,026,437,131 (1,026.4M-1,033.6M) | 6.6-24.4 | 118.9-153.2 | 0.20-0.25 |

`pages_changed` was identical across all 5 runs of each mode (full 1,295; latest 648; firstbuild 1,295).

## Reading

* `latest` does write less than `full` at seed time: 648 vs 1,295 pages (-50%), 14% fewer
  instructions (755.6M vs 878.1M, the ranges do not overlap).
* The saving is deferred, not removed: `firstbuild` ends at the same 1,295 changed pages as `full`
  (the normalisation rewrites every retained donor row), and costs more instructions in total
  (1,026.4M vs 878.1M) because it rebinds and then normalises. On this 2-generation store the
  difference is the page count above; it grows with the number of retained generations.
* No timing ratio is asserted anywhere in the tests; this file is the only place wall time appears.
